# 基板（官方基座）支持克隆与文字（语音设计）混用吗？

> **结论先给**：
> - **库层面：支持。** 克隆音色与属性描述可以**同时**生效，属性会真实调制克隆的音色（实测 F0 变化达 65%）。
> - **本机服务层面：不支持（本机主动做的选择）。** 命中克隆音色时属性串被丢弃。
> - **属性串自身：不能中英混写**（会被归一化，不是报错），**同类属性不能给两个**（报错）。

> 核实方式：库源码逐行阅读 + 本机实跑（A/B/D/E 四组对照组 + F0 调制判定）。
> 源码位置：`omnivoice/models/omnivoice.py`、`omnivoice/utils/voice_design.py`；本机逻辑：`server.py`。

---

## 一、先分清「三种混用」，答案各不相同

| 问题 | 答案 | 依据 |
|---|---|---|
| ① 克隆音色 + 任意新文本 | ✅ **支持**（官方核心能力） | `create_voice_clone_prompt` → `generate(voice_clone_prompt=...)` |
| ② 克隆音色 **+ 属性描述串**（instruct） | ⚠️ **库支持 / 本机服务不支持** | 见 §2、§3 |
| ③ 属性描述串**内部**中英混写 | ⚠️ **不支持**，但不报错——被静默归一化 | 见 §4 |

---

## 二、库层面为什么能共存（源码证据）

`omnivoice/models/omnivoice.py` 的 `_prepare_inputs`（约 1220-1258 行）：

```python
style_text = ""
if denoise and ref_audio_tokens is not None:
    style_text += "<|denoise|>"
style_text += f"<|lang_start|>{lang_str}<|lang_end|>"
style_text += f"<|instruct_start|>{instruct_str}<|instruct_end|>"   # ← 无条件写入
...
parts = [style_tokens, text_tokens]
if ref_audio_tokens is not None:
    parts.append(ref_audio_tokens.unsqueeze(0).to(self.device))     # ← 参考音频是另外一段
parts.append(target_audio_tokens)
cond_input_ids = torch.cat(parts, dim=2)
```

**两处关键**：
1. `<|instruct_start|>...<|instruct_end|>` 是**无条件**写进 style token 的——哪怕只做克隆，
   那里也会填 `<|instruct_start|>None<|instruct_end|>`。
2. 参考音频是**独立的一段**拼进 `cond_input_ids`，与 style token 并列，不是替代关系。

→ 模型在推理时**同时看得到**属性描述与参考音频，二者不是 if/else。
**唯一的门槛是 `_resolve_instruct()` 的校验**（属性串必须合法，见 §4）。

## 三、本机服务为什么「不支持」

`server.py` 两处叠加造成：

**① `resolve_voice()`（约 869-883 行）**——命中克隆就直接返回 `instruct=None`：

```python
def resolve_voice(voice, instructions, voices, use_instructions=None):
    """... the two modes are mutually exclusive: cloning carries its own
    timbre, so no instruct is sent."""
    key = (voice or "").strip()
    if key in clone_names():
        return None, get_clone(key)          # ← instruct 直接置 None
    return pick_instruct(key, instructions, voices, use_instructions), None
```

**② `run_generate()`（约 915-918 行）**——二选一：

```python
if clone is not None:
    kwargs["voice_clone_prompt"] = clone
else:
    kwargs["instruct"] = instruct or None    # ← 有 clone 就永远不传 instruct
```

> 这是**本机服务的保守设计**（避免两个音色来源打架），不是上游库的硬限制。
> 要放开只需把 ① 改成同时返回 instruct、② 改成两者都传——但要先听感验证是否稳定。

## 四、属性串自身的规则（`_resolve_instruct`，约 1492-1621 行）

### 白名单（23 英 / 25 中，**无情绪维度**）

| 类别 | 英文 | 中文 |
|---|---|---|
| gender | male, female | 男, 女 |
| age | child, teenager, young adult, middle-aged, elderly | 儿童, 少年, 青年, 中年, 老年 |
| pitch | very low pitch, low pitch, moderate pitch, high pitch, very high pitch | 极低音调, 低音调, 中音调, 高音调, 极高音调 |
| style | whisper | 耳语 |
| accent | american / british / australian / chinese / canadian / indian / korean / portuguese / russian / japanese accent | —（仅英文） |
| dialect | —（仅中文） | 河南话, 陕西话, 四川话, 贵州话, 云南话, 桂林话, 济南话, 石家庄话, 甘肃话, 宁夏话, 青岛话, 东北话 |

### 三条硬规则

| 规则 | 行为 | 例子 |
|---|---|---|
| **不认识的属性 → 报错** | `ValueError`，并给最接近的建议 | `angry, excited` → 报错（`angry` 是情绪词，不在白名单） |
| **同类给两个 → 报错** | 每类至多一项 | `male, female` → 报错 |
| **方言 + 口音混用 → 报错** | 跨语言属性冲突 | `四川话, british accent` → 报错 |
| **中英混写 → 不报错，但被归一化** | 按「有方言→中文、有口音→英文、否则跟随文本语言」统一到单一语言 | `male, 老年` → 归一化成同语言的一套词 |
| **分隔符错误 → 自动修** | 中文用半角逗号 / 英文用全角逗号都会被修好 | `女，青年` ↔ `female, young adult` |

> ⚠️ 中英混写的坑在于**它不报错**——你以为混着写了，实际上其中一半被丢弃/转换了。

## 五、本机实测（2026-10-22）

### 5.1 库层面：克隆 + 属性确实共存

用官方基座（`models/OmniVoice`），中文测试句 `我不太确定我们该不该这么做，你说呢？`：

| 组 | 参数 | 时长 | RMS | 频谱质心 | 动态范围 | 结果 |
|---|---|---:|---:|---:|---:|---|
| A | 克隆 only | 2.61 s | 0.0713 | 2048.4 | 5.37 | ✅ |
| B | 属性 only（`female, young adult, high pitch`） | 3.34 s | 0.0956 | 1911.4 | 3.66 | ✅ |
| C | **克隆 + 属性（同时给）** | 2.50 s | 0.0764 | 1746.0 | 4.62 | ✅ **成功** |
| D | 克隆 + 非法属性（`angry, excited`） | — | — | — | — | ❌ **ValueError**（校验器照样生效） |
| E | 克隆 + 中文属性（`女，青年，高音调`） | 2.65 s | 0.0825 | 1820.8 | 4.88 | ✅ |

→ **C 组与 A/B 都不同** → 两者同时喂进去时输出确实是「克隆音色 + 属性调制」的混合结果，
而不是任一方的纯输出。**D 组**说明属性串的合法性校验在克隆模式下**不会因为有克隆而被跳过**。

### 5.2 属性是否真的调制了克隆？用 F0 判定

用两个不同参考音频，各加一组性别/音高相反的属性：

| 用例 | 克隆基线 F0 | 加属性后 F0 | 变化 |
|---|---:|---:|---|
| A 克隆（`ja_Ganyu_0001`） | 324.3 Hz | **113.2 Hz**（`male, low pitch`） | **−65%** ⬇️ 明显压低 |
| B 克隆（`ja_Ganyu_0009`） | 338.0 Hz | 342.9 Hz（`female, high pitch`） | +1.5% ≈ 不动 |

**判定**：
- `male, low pitch` 对克隆有**极强**的调制（音高腰斩）。
- `female, high pitch` 对一个本就是高音的克隆**几乎无影响**——这符合直觉：
  **属性是相对参考音色的偏移指令，不是绝对设定**；当参考音色已经满足该属性时，位移趋近于零。

> 📌 **可用性推论**：想用克隆但想改性别/音高，**改「参考音频」比加属性更可靠**；
> 属性只适合做小幅偏移（如把克隆音高整体压低一点）。

## 六、给使用者的结论

| 你想做的 | 怎么做 | 注意 |
|---|---|---|
| 克隆某个角色的音色念新台词 | ✅ 直接用，本机服务已支持 | 最稳的路线 |
| 克隆 + 想改音高/性别 | ⚠️ 库层面可行（`generate(voice_clone_prompt=..., instruct=...)`），**本机服务当前不开放** | 「往下压」类指令有效，「往上抬」对已高音的克隆几乎无效 |
| 纯文字造声（无参考音频） | ✅ `voice` 字段直接填属性串，如 `female, elderly, 四川话` | 属性串必须全英文或全中文，不能混 |
| 混写中英属性 | ❌ 别干 | 不报错但会静默丢一半 |

> **对约战日文的实际建议**：属性调制这条路是**在英语/中文属性体系上训练**的，
> 对日文克隆的调控力度**未验证**。日文演出仍建议
> **「角色克隆 + 13 个非语言符号 + 情绪参考音频拼接」**这条已验证的路线。
