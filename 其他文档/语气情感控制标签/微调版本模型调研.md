# 微调版本模型调研（OmniVoice 全参微调 + LoRA + 社区权重）

> 结论先行：
> 1. 官方提供**两条**微调管线——**全参微调**（300k 步、8 卡级）与 **LoRA 参数高效微调**（仅 ~3% 参数可训练）。
> 2. 社区已发布的是**按语言提升克隆质量的 LoRA 适配器**（`amanuelbyte/omnivoice-lora-zh|fr|ar`），**不是情绪微调**。
> 3. **本机（RTX 3080 10GB / 15.9GB 内存）无法本地训练**；全参微调需 8 卡集群，LoRA 也建议 ≥24GB 显存。
> 4. （2026-10-22 扩大搜索补充）情绪/控制词微调再确认三类——但**均为全参微调**（ModelsLab 英文行内标签、issai 哈萨克语 instruct 维度、multimodalart 词级韵律向量），LoRA 侧至今只有**语言克隆增强**类。另发现两个**语言增强**全参微调（库尔德语 `Dezheen89/omnivoice-badini`、格鲁吉亚语 `NMikka/omnivoice-finetuned-ka`）。
> 5. **`issai/KazGenericTTS` 在本环境无法获取**：仓库 403 门控 + 官方端点（huggingface.co）完全不可达（curl 返回 HTTP 000）；仅 `hf-mirror.com` 可达但要求授权 token。如需实测，需用户提供**已获授权**的 HF token 走镜像侧下载。
> 6. 本机已实拉 `ModelsLab/omnivoice-singing`（全参·情绪）与 `amanuelbyte/omnivoice-lora-zh`（LoRA·中文克隆）并跑通推理，结论见第六节。

## 一、官方全参微调（Full Finetuning）

来源：`docs/training.md`、`examples/`（数据准备 → 分词 → 训练 → 评估）

### 1.1 数据格式（JSONL manifest）
每行一个样本，字段：
```json
{"id": "sample_001", "audio_path": "/data/a.wav", "text": "转录文本", "language_id": "en"}
```
- `extract_audio_tokens` 将音频分词成 **WebDataset shards**（训练时流式读取）。

### 1.2 关键训练配置
| 字段 | 值 | 说明 |
|------|----|------|
| `llm_name_or_path` | `Qwen/Qwen3-0.6B` | 基座 LLM |
| `init_from_checkpoint` | `k2-fsa/OmniVoice` | 从官方预训练初始化（微调时） |
| `steps` | **300,000** | 总步数（全参） |
| `learning_rate` | **1e-4** | 峰值 LR |
| `batch_tokens` | 8192 | 每卡 token 预算（主要显存控制） |
| `attn_implementation` | `flex_attention`（默认）/ `sdpa` | flex 需 PyTorch≥2.5 + Ampere+ |

- **flex_attention** 用序列打包（sequence packing）`[1, C, batch_tokens]`；**sdpa** 用长度分组 padding `[B, C, max_len]`。
- sdpa 额外字段：`max_sample_tokens=2000`、`min_sample_tokens=50`、`max_batch_size=64`。

### 1.3 启动命令
```bash
accelerate launch --gpu_ids "0,1,2,3,4,5,6,7" --num_processes 8 \
    -m omnivoice.cli.train \
    --train_config config/train_config_emilia.json \
    --data_config config/data_config_emilia.json \
    --output_dir exp/omnivoice_emilia
```
- 续训：`resume_from_checkpoint`，或 `init_from_checkpoint` 从某 checkpoint 起微调。
- 日志：TensorBoard `--logdir exp/.../tensorboard`。

### 1.4 评估指标
- **WER**（词错率，ASR 验证）、**说话人相似度**（speaker similarity）、**UTMOS**（主观音质打分）。

### 1.5 硬件需求
- 官方示例 **8× GPU**（A100 级）；`batch_tokens=8192` × 8 卡，300k 步 → 集群级训练。
- 显存随 `batch_tokens` 线性增长，降低该值可减显存但拉长训练。

## 二、官方 LoRA 微调（参数高效）

来源：`docs/lora_finetuning.md`（`pip install "omnivoice[lora]"` 或 `pip install peft`）

### 2.1 与全参微调的配置差异
在 finetune 配置基础上加 LoRA 字段（默认 `use_lora: false` 即全参）：

| 字段 | 值 | 说明 |
|------|----|------|
| `use_lora` | `true` | 开启 LoRA |
| `lora_r` | 16 | 秩（越大容量越高） |
| `lora_alpha` | 32 | 缩放（`alpha/r`） |
| `lora_dropout` | 0.05 | 适配器内 dropout |
| `lora_bias` | `"none"` | |
| `lora_target_modules` | q/k/v/o_proj + gate/up/down_proj | LLM 注意力/MLP 投影 |
| `lora_modules_to_save` | `audio_embeddings`, `audio_heads` | OmniVoice 专用音频 I/O 层，**全参训练**并随适配器保存 |
| `learning_rate` | **1e-4**（高于全参的 5e-5） | 适配器从零训，需更高 LR |

- 启动行打印：`trainable params: 19,316,736 || all params: 631,894,016 || trainable%: 3.0570`
- 原基座权重磁盘上**不动**，适配器可随时卸除以恢复原模型。

### 2.2 启动
```bash
accelerate launch --gpu_ids "0,1" --num_processes 2 \
    -m omnivoice.cli.train \
    --train_config examples/config/train_config_finetune_lora.json \
    --data_config examples/config/data_config_finetune.json \
    --output_dir exp/omnivoice_finetune_lora
# 或：bash examples/run_finetune_lora.sh
```

### 2.3 适配器推理（不落盘，PEFT 依赖）
```bash
omnivoice-infer --model k2-fsa/OmniVoice \
    --lora_adapter exp/omnivoice_finetune_lora/checkpoint-500 \
    --text "..." --ref_audio ref.wav --ref_text "..." --output out.wav
```
`--lora_adapter` 接受含 `adapter_config.json` + `adapter_model.safetensors` 的目录。

### 2.4 适配器合并（部署时免 PEFT）
```bash
omnivoice-merge-lora --base_model k2-fsa/OmniVoice \
    --lora_adapter exp/omnivoice_finetune_lora/checkpoint-500 \
    --output_dir exp/omnivoice_finetune_lora/merged
```
合并后是**普通 OmniVoice 检查点**，可直接 `from_pretrained(".../merged")` 用。

### 2.5 检查点结构
```
checkpoint-500/
├── adapter_config.json        # PEFT 配置（小）
├── adapter_model.safetensors  # LoRA 权重 + audio_embeddings/audio_heads（小）
├── tokenizer.json / tokenizer_config.json
├── model.safetensors          # accelerate 全量训练状态（大）
├── optimizer.bin / scheduler.bin / random_states_0.pkl  # 续训用
```
> 部署只需保留 `adapter_config.json` + `adapter_model.safetensors` + tokenizer；其余可删。

from omnivoice import OmniVoice

## 四、硬件需求与本地可行性（本机视角）

来源：`docs/training.md`、LoRA 文档、cnblogs 分析、本机硬件基线（RTX 3080 10GB / 15.9GB 内存）。

| 训练方式 | 最低显存 | 本机（3080 10GB） | 结论 |

  1. `PeftModel.from_pretrained(base.llm, "<权重目录>/...")` → PEFT 把 Windows 盘符路径当 HF repo id 做 `validate_repo_id` 校验，拒绝带盘符路径；
