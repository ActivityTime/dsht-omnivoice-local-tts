# 情绪与语气控制标签总表（OmniVoice 官方 + 社区）

> ⚠️ **更正（2026-10-22 补充调研）**：下文的「没有情绪标签」**仅指官方基座 `k2-fsa/OmniVoice`**。社区已有多个落地的情绪 / 控制词微调（同架构、drop-in 替换），见文末「五、社区已落地的情绪 / 控制词微调」与 `微调版本模型调研.md` 第三节。速览：
> - `ModelsLab/omnivoice-singing`：行内情绪标签 `[happy]/[sad]/[angry]/[excited]/[calm]/[nervous]/[whisper]`（英文数据训练）
> - `issai/KazGenericTTS`：`instruct` 内 `emotion` 维度 {angry, disgusted, fearful, happy, neutral, sad, surprised}（哈萨克语，含 LoRA 变体）
> - `multimodalart/omnivoice-word-control`：词级 5 维韵律控制向量（时长 / 停顿 / 能量 / 音高 / 音高轮廓，英文 WordVoice-5A）

> 结论先行：**官方基座 OmniVoice 没有独立的「情绪 / 语气」维度标签。**
> - 真正能影响「情绪 / 语气」的只有 **13 个非语言符号**（笑声、叹气、疑问、惊讶、不满…）。
> - 语音设计（voice design）里的 `style` 类**只有 `whisper`（耳语）一种**，其余是性别/年龄/音高/口音/方言等**说话人属性**，不是情绪。
> - 作者已在 issue #78 确认：原生不支持 `[happy]`/`[sad]` 这类情绪标签，因为缺少带情绪标注的数据集。

## 一、官方可控标签全清单

### 1.1 非语言符号（Non-verbal symbols）—— 唯一直接的情绪 / 语气信号

源码位置：`omnivoice/models/omnivoice.py:1652-1654` 正则
`r"\[(laughter|sigh|confirmation-en|question-en|question-ah|question-oh|question-ei|question-yi|surprise-ah|surprise-oh|surprise-wa|surprise-yo|dissatisfaction-hnn)\]"`

| 标签 | 推测含义 | 典型用法 |
|------|---------|---------|
| `[laughter]` | 笑声 | `[laughter] 你真的逗死我了` |
| `[sigh]` | 叹气 | `[sigh] 唉，又来了` |
| `[confirmation-en]` | 确认语气（英文语境） | 肯定/应答语调 |
| `[question-en]` | 疑问语气（英文） | 句尾上扬的疑问 |
| `[question-ah]` | 疑问，尾音 `ah` | 带「啊？」的疑惑 |
| `[question-oh]` | 疑问，尾音 `oh` | 带「哦？」的疑惑 |
| `[question-ei]` | 疑问，尾音 `ei` | 带「诶？」的疑惑 |
| `[question-yi]` | 疑问，尾音 `yi` | 带「咦？」的疑惑 |
| `[surprise-ah]` | 惊讶，尾音 `ah` | 「啊！」的吃惊 |
| `[surprise-oh]` | 惊讶，尾音 `oh` | 「哦！」的吃惊 |
| `[surprise-wa]` | 惊讶，尾音 `wa` | 「哇！」的吃惊 |
| `[surprise-yo]` | 惊讶，尾音 `yo` | 「哟！」的吃惊 |
| `[dissatisfaction-hnn]` | 不满 / 不悦（哼声 `hnn`） | 嫌弃、不以为然的语气 |

> ⚠️ 官方文档仅列出标签名、未逐条释义；上表「推测含义」依据命名与语义归类。
> 用法：直接写在 `text` 里，例如
> ```python
> audio = model.generate(text="[laughter] You really got me. I didn't see that coming.")
> ```
> 这些符号在 `text.py` 的 `normalize_text` 中会被 `_BRACKET_TAG_RE` 保护、不会被数字归一化破坏。
> **覆盖的「情绪」极其有限**：只有「笑/叹气/疑问/惊讶/不满」五类大类，且无法调强度、无法指定「愤怒地说」「悲伤地说」。

### 1.2 语音设计属性（Voice Design）—— 说话人属性，不是情绪

源码位置：`omnivoice/utils/voice_design.py` `_INSTRUCT_CATEGORIES`
传入 `instruct="..."`，逗号分隔，跨类自由组合；同类互斥。

| 类别 | 可选值（英 / 中） | 是否情绪 |
|------|------------------|---------|
| Gender 性别 | male/男、female/女 | 否 |
| Age 年龄 | child/儿童、teenager/少年、young adult/青年、middle-aged/中年、elderly/老年 | 否 |
| Pitch 音高 | very low/极低、low/低、moderate/中、high/高、very high/极高 | 间接（音高≠情绪） |
| Style 风格 | **whisper / 耳语（唯一一种）** | 勉强算「表达方式」，非情绪 |
| Accent 口音（仅英文生效） | american/british/australian/chinese/canadian/indian/korean/portuguese/russian/japanese | 否 |
| Dialect 方言（仅中文生效） | 河南话/陕西话/四川话/贵州话/云南话/桂林话/济南话/石家庄话/甘肃话/宁夏话/青岛话/东北话 | 否 |

> 关键点：**`style` 类只有 `whisper` 一个**，官方没有 `angry`/`happy`/`sad` 等 style。
> 语音设计仅在**中、英**数据上训练（官方 README 原话），对日/西/法等语言是泛化、可能不稳定。

### 1.3 发音纠正（间接影响韵律）

- **中文**：拼音 + 声调数字，如 `打ZHE2出`、`SHE2本` —— 修正特定字发音，间接改变韵律。
- **英文**：CMU 音素（大写 + 括号），如 `[B EY1 S]`、`[B AE1 S]` —— 覆盖默认英文发音。
- 同样在 `normalize_text` 中被 `_PINYIN_TONE_RE` / `_BRACKET_TAG_RE` 保护。

### 1.4 生成参数（与情绪无关，但影响节奏 / 随机性）

来自 `docs/generation-parameters.md`，经 `model.generate(...)` 或 `OmniVoiceGenerationConfig` 传入：

| 参数 | 默认 | 说明 | 与情绪关系 |
|------|------|------|-----------|
| `num_step` | 32 | 迭代去掩码步数（16 更快） | 无关（质量/速度） |
| `denoise` | True | 预置 `<|denoise|>` 更干净语音 | 无关 |
| `guidance_scale` | 2.0 | CFG 强度 | 无关（贴合度） |
| `t_shift` | 0.1 | 噪声 schedule 时间偏移 | 无关 |
| `position_temperature` | 5.0 | mask 位置选择温度（0=贪心） | 影响随机性，非情绪 |
| `class_temperature` | 0.0 | token 采样温度（0=贪心） | 影响随机性，非情绪 |
| `layer_penalty_factor` | 5.0 | 深层 codebook 惩罚 | 无关 |
| `speed` | None(=1.0) | 语速（>1 更快） | **间接**：语速可被当作「急切/平静」的弱信号 |
| `duration` | None | 固定时长（覆盖 speed） | 间接（同上） |
| `preprocess_prompt` / `postprocess_output` | True | 参考音频/输出后处理 | 无关 |
| `pad_duration` / `fade_duration` | 0.1 | 静音/淡入淡出 | 无关 |
| `audio_chunk_duration` / `audio_chunk_threshold` | 15/30 | 长文本分段 | 无关 |

> **没有任何一个参数是「情绪 / 语气」控制项。** `speed` 是唯一可被「借用」来表达急切/平静的参数，但它是全局语速、不能句中切换。

## 二、官方明确「不支持」的情绪标签（证据）

**GitHub issue #78「Emotion / Tone control」（2026-04）**

- 提问者希望有 `[whispering]`/`[excited]`/`[loud]` 这类行内情绪/语气标签。
- **alephpi（官方）**：「It is realizable, please check Fishspeech S2. **This requires much more data to train, and I think it is currently out of scope for OmniVoice.**」
- **zhu-han（原作者）**：「**this feature would require a dataset with such annotations to support these tags. We currently do not have such a dataset.**」
- 社区 workaround（Matsalviano）：准备带情绪的参考音频片段（`angry01.mp3`、`sad01.mp3`、`excited01.mp3`），分段推理后拼接。

> 结论落地：**原生 `[happy]`/`[sad]`/`[angry]` 不存在**；想得到情绪，要么用 13 个非语言符号里凑得上的（笑/叹气/惊讶/疑问/不满），要么走「情绪参考音频 + 克隆 + 拼接」的 workaround，要么等官方出带标注数据的微调版。

## 三、竞品 / 社区怎么做「情绪控制」（对照参考）

来源：`as-repo1/OmniVoice-Studio` `docs/specs/01-expressive-tts.md`、cnblogs 开源分析。

| 系统 | 情绪控制方式 | 说明 |
|------|------------|------|
| **ElevenLabs v3** | 行内音频标签 `[excited]`/`[whispers]`/`[sigh]`/`[laughs]` + 情景/反应标签 | 商业闭源，表达性最强 |
| **CosyVoice 3** | 自然语言 instruct + 行内 `[laughter]`/`[breath]` | 阿里开源 |
| **IndexTTS2** | **8 维情绪向量** `[happy, angry, sad, afraid, disgusted, melancholic, surprised, calm]` 或情绪参考音频 | 情绪表达最结构化 |
| **OmniVoice（官方现状）** | 仅 13 非语言符号 + whisper；**无 `[happy]`/`[sad]`** | 需微调才支持情绪标签 |
| **OmniVoice-Studio（社区 fork 设想）** | 计划引入 SSML-lite `[slow]`/`[fast]`/`[emphasis]` + 复用现有 `[...]` 保护机制 | Spec 01 提议，目标 v0.3.x，尚未落地 |

> 对「约会大作战」这类**强情绪、多角色**素材，若严格要「愤怒/悲伤/害羞」等细腻情绪，OmniVoice 当前能力弱于 IndexTTS2 / ElevenLabs；但用「角色克隆音色 + 非语言符号 + 情绪参考音频拼接」已能覆盖大部分演出需求（见下节）。

## 四、本机可用方案（落到 `<项目根>` 实操）

1. **直接用 13 个非语言符号**（已源码确认）：在 `text` 中插入 `[laughter]`/`[sigh]`/`[question-*]`/`[surprise-*]`/`[dissatisfaction-hnn]`。
   - 经 `server.py` 生成端点或 `omnivoice-infer --text "..."` 均可。
2. **whisper 耳语**：`instruct="female, whisper"` 之类。
3. **情绪参考音频拼接（issue #78 社区法）**：
   - 对每个角色准备 `angry.wav`/`sad.wav`/`happy.wav` 等带情绪短样本；
   - 按句切分文本，逐句用对应情绪样本做克隆推理；
   - 用 Audacity / ffmpeg 拼接成连续演出。
4. **`speed` 弱信号**：急切句用 `speed=1.15`，平静句用 `speed=0.9`（全局，不能句中切）。
5. **不要做的事**：指望 `instruct` 里写 `angry`/`sad` —— 不在白名单，会被忽略或报错（本机 `voice_design.py` 的 `_INSTRUCT_ALL_VALID` 校验只认上表 6 类）。

> 下一步若需要，我可以在本机跑一条 `[laughter]` + 克隆的样例，实证非语言符号在 `<项目根>` 链路上的实际产出（当前为源码级确认，尚未在本机实跑验证）。

## 五、社区已落地的情绪 / 控制词微调（补充）

> 上一轮遗漏项。以下均为 `k2-fsa/OmniVoice` 的**同架构 drop-in 微调**（Qwen3-0.6B + HiggsAudioV2@24kHz，推理 API 不变，仅换 `model` id 或指向本地权重目录）。

### 5.1 情绪标签：`ModelsLab/omnivoice-singing`（同 `Kremon96/OmniVoice_Singing`）
- 两阶段微调（唱歌 2500 步 + 情绪 2500 步，2 GPU，bf16，lr 3e-5）。
- 新增行内标签：`[singing]` + 情绪 `[happy]`/`[sad]`/`[angry]`/`[excited]`/`[calm]`/`[nervous]`/`[whisper]`。
- 数据：CREMA-D + RAVDESS + Expresso（英文情绪库）+ GTSinger（唱歌）。
- 用法：`model.generate(text="[happy] I just got the best news!", language="English", guidance_scale=3.0)`（推荐 `guidance_scale=3.0` 让标签更明显）。
- 局限：`[calm]`/`[excited]` 仅 ~190 样本，较弱；情绪标签基于**英文**数据，跨语言（如日文）未验证。

### 5.2 情绪作为语音设计维度：`issai/KazGenericTTS`
- 全参微调（5000 步，H100）+ 另发 **LoRA 变体**（r=16/α=32，≈4.4% 参数）。
- `instruct` 内新增 `emotion` 维度：`{angry, disgusted, fearful, happy, neutral, sad, surprised}` + 18 个 NVV 行内标签（`[laugh]`/`[sigh]`/`[gasp]`…）。
- 数据：KazParaD（哈萨克语）。证明情绪完全可以做成 voice-design 的一个维度，只是需要带标注数据。

### 5.3 词级韵律控制向量：`multimodalart/omnivoice-word-control`
- 全参微调（40k 步，单 A100-40GB，~6h，lr 5e-5），数据 WordVoice-5A（英文，~2138h）。
- 在**每个词前**插入 special token，做 5 维韵律控制：
  | token | 控制 | 离散化 |
  |-------|------|--------|
  | `<dur=...>` | 词时长 | 40ms 帧（40ms–2.56s） |
  | `<sil=...>` | 词后停顿 | b0 无 … b4 长（>0.4s） |
  | `<eng=...>` | 能量 | 20 档 [0,1] |
  | `<pit=...>` | 音高（核心 F0） | 20 档 [−1,1] |
  | `<cnt=...>` | 音高轮廓 | 7 种形态 |
- 共 116 个控制 token 加入 tokenizer；这就是你要找的「控制词 / 韵律向量」微调，粒度到词级。

### 5.4 落地到本机的注意
- **兼容性**：三个都是完整 checkpoint，本地 `omnivoice` 库可直接 `from_pretrained(...)`；本机 RTX 3080 10GB（bf16 已跑通基座）显存足够加载同尺寸微调。
- **许可证**：OmniVoice 基座为 **CC-BY-NC**（Emilia 等数据限制），上述微调继承 NC，**仅非商用**；商用需另寻授权或自训。
- **语言域**：情绪 / 词级控制训练语料均为**英文 / 哈萨克语**。**对约战素材的日文，跨语言情绪/韵律未经验证，可能不稳定或失效**——日文演出仍建议「角色克隆 + 13 非语言符号 + 情绪参考音频拼接」。
- OmniVoice-Studio 的 expressive TTS spec 01 目前仍是 **Proposed（未实现）**；第三方在线站 `omnivoiceai.net` 号称 8 维情绪滑块属商业服务、非开源权重，不计入。
